# Contributing to the Jhol site

Write for developers choosing whether Jhol fits their project. Keep
installation steps tied to a named release and verify command examples against
that release. Explain current limits alongside capabilities, especially for
ecosystem adapters and optional services.

Use Jhol's own terminology and visual identity. Do not reuse another product's
copy, layout, illustrations, or unsupported claims. Keep source behavior and
schemas authoritative in the main repository; link to them instead of
maintaining a conflicting second specification.
