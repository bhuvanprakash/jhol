# Contributing to Jhol projects

Start with the contribution guide in the repository you are changing. Each
project owns its build, review, and release instructions; this organization
guide sets shared expectations only.

- Describe the user problem and the smallest change that solves it.
- Keep ecosystem-native manifests, lockfiles, and version semantics intact.
- Include evidence for behavior changes, and label checks that were not run.
- Explain new network access, script execution, database writes, process
  launches, or remote uploads.
- Use compatibility standards where users need interoperability. Keep Jhol's
  implementation, naming, visual identity, and product claims its own.
- Never include credentials, private registry data, generated build output, or
  cherry-picked benchmark results.

The main repository's [contribution guide](https://github.com/bhuvanprakash/jhol/blob/main/CONTRIBUTING.md)
contains its current setup and workflow. Repository-specific instructions take
precedence for that project's commands and checks.
