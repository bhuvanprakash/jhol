# Jhol — Technical Report

**Date:** 2026-11-07 · **Scope:** package manager + JholVM engine · **Method:** measure, then change; node is the oracle for the engine, npm's own lockfiles and registry are the oracle for the package manager.

---

## 0. Executive summary

This session had one organising rule: **no claim without a command beside it.** That rule produced three outcomes.

1. **The package manager became correct where it had been quietly lying.** A tampered package and an unauthorised directory both used to survive an install while a *deleted* package was repaired — three behaviours, one cause: five components independently decided "already up to date" from mtimes, proofs and fingerprints that cannot see inside the tree. There is now one predicate (`jhol-treecheck`) consulted before any lane and after every lane.

2. **The resolver got fast enough to stop being the bottleneck.** Chart assembly fell 12.4× (141.6 ms → 11.4 ms) by compiling semver ranges once instead of once per published version; the metadata load fell 28× (426 ms → 15.2 ms) with a purpose-built binary index. Resolution is now ~15 ms for a 275-package graph, which is why agent-facing features ("price this plan", "why not this range") cost milliseconds.

3. **New capability that is structurally hard to copy**: history (`--as-of`), licence policy and CVE exclusion are *resolution inputs*, not audits; models are first-class artifacts with header-only inspection and inode-level dedupe; Python wheels resolve *and* install against detected hardware; environments fork in 797 ms for zero bytes; attestations are deterministic and produced by the same verifier that enforces them. All of it falls out of one representation choice — versions are ordinals in bitmaps, so a policy is an intersection.

The engine side closed **seven** gaps, each found by measurement and pinned against node: temporal dead zone, an arrow-function compiler panic, strict-mode assignment, a real `Symbol` primitive, well-known symbols, array destructuring via the iterator protocol, and `Promise` with node-exact microtask ordering. The corpus is 50 node-verified pairs; a 20-idiom differential sweep matches 19/20 (the miss was `typeof Symbol`, since fixed).

Everything below is either measured or explicitly marked **not measured**.

# Part I — The package manager

## 1.1 The install pipeline, top to bottom

```
main()
  └─ plain_install_fully_settled()            ← one freshness authority
        Match      → print "Up to date (N)" and exit
        Extraneous → warn, keep the tree (pruning is opt-in)
        otherwise  → continue
  └─ ProjectLock::acquire(".")                ← flock, kernel-released
        └─ lane selection
              L0 prepared-tree proof
              capsule (prepared layout)
              L0 bundle projection
              fresh-project replay
              traditional: expand → resolve → download → extract
        └─ reconcile_tree()                   ← post-lane truth check
        └─ lifecycle / patches / engines / receipts
```

**Why the freshness authority came first, and why at the entry point.** Five gates used to answer "current?" with five kinds of evidence: a `.jhol-ok` mtime, a prepared-tree proof, a bundle projection, `lockfile_fingerprint_matches()`, a daemon verdict — plus `nm_fresh()` inside the installer. A fingerprint can prove nothing changed *around* the tree; none could prove the tree *is what the lockfile authorises*. Gating call sites one at a time took four attempts across this project; the durable fix was to move the verdict **inside** `lockfile_fingerprint_matches()` so every caller inherits it, and to consult it once at the entry point.

**The predicate** (`crates/jhol-treecheck`, 15 tests) returns exactly one of:

```
Match | Missing{path} | Wrong{path,want,got} | Extraneous{path} | Unverified{reason}
```

One `package.json` read per installed package, no archive hashing. `reconcile_tree()` verifies, prunes what the lockfile never authorised (needs no resolution), and re-verifies.

Two details matter more than they look:

* **platform applicability.** esbuild publishes 21 packages, one per target. `verify` demanded all of them and reported `@esbuild/aix-ppc64` missing on darwin/arm64. `entry_platform_applies` now evaluates `os`/`cpu`/`libc` with npm's semantics (allow-lists, `!` denies, `libc` only distinguishes Linux) and excludes inapplicable entries from what must exist *and* from the integrity gate.
* **a lockfile that omits packages it installed is not an authority.** `express@latest` installed 68 packages and wrote 56 entries, with none of the 12 appearing in any dependency map. Pruning against that deleted real code — twice, before I noticed. Pruning became opt-in; the incompleteness is reported.

## 1.2 The lock

`flock` on `.jhol/install.lock`, held for the life of a process that writes the tree; read-only commands never take it; warm installs return before it.

The first implementation used `create_new` + a pid file, and the reproduction found its race in minutes: between create and write, a second process reads an **empty file**, calls the content garbage, treats the lock as stale, removes it and proceeds — the exact bug the lock exists to prevent. `flock` deletes the class: ownership is the open file description, so there is nothing to read and nothing to race, and the kernel releases it on any exit path — which matters because the CLI calls `std::process::exit` widely and that bypasses `Drop`.

## 1.3 JAGR-∞ — the resolver

**Representation.** A package's published versions are sorted by semver and numbered from 0. A domain is a `VersionBitmap`: `words: Vec<u64>`, `ordinal_lo`, `ordinal_hi`, 64 versions per word. `intersect`/`union` are **base-aware** — same base is a word-wise fast path, different bases rebase onto the overlap — because word offsets are meaningless without their base. An edge carries `required_mask`: the dependent's requirement expressed in the *target's* ordinals, built by evaluating the raw spec against the target's published versions.

**Propagation** is a fixpoint over a dirty queue: monotone (domains only shrink), idempotent (a fixpoint stays fixed), and order-independent (incoming lists and the initial queue are sorted, because a chart must be a function of its inputs).

**Search** is most-constrained-first, tie-broken by package id, highest version first, with tentative choices propagated into dependents and restored on backtrack; `JAGR_SEARCH_BUDGET` (20 000) bounds it and exhaustion is reported.

**Instances** (`jagr_nest`). A flat domain cannot represent npm's tree: `chalk@4` and `chalk@2` coexist because `node_modules` is a tree. So resolution creates **instances**: a requirement creates one, and only requirements whose ranges cannot share a version create a second. Every instance records `required_by: [(dependent, spec)]` — its derivation.

```
jest@29.7.0: 270 instances, 249 packages, 19 packages with >1 version, ~103 ms
  ansi-styles  6.2.3, 5.2.0, 4.3.0
  ansi-regex   6.5.0, 5.0.1
```

**Honest history.** Before this, `jest` "resolved" by *violating* requirements: `VersionBitmap::intersect` compared bitmaps anchored at different ordinals, silently accepting incompatible versions, and the nested layout then produced a plausible tree. Correct intersections expose the truth — which is why the flat model had to be replaced rather than tuned.

## 1.4 The three performance wins, in the order measurement dictated

**Method.** `resolve_bench` over the real packument cache (275–344 documents, 6 715 edges), phase timings via `JAGR_PROFILE_CHART=1`. Two confident hypotheses were measured and discarded before the real cause was found:

| hypothesis | measurement | verdict |
|---|---|---|
| semver parsing of *versions* dominates | 148 → 140 ms after parsing once per package | wrong |
| JSON extraction dominates | **2.4 ms of 144 ms** | wrong |
| **mask assembly dominates** | **141.6 ms** | right |

`version_satisfies_parsed` is written for one-off checks: it trims, probes for an exact pin, and takes a **mutex-guarded global cache lock per call** — while selecting a version asks it once per published version of the target. `compile_spec` decides the variant once (`Any`, `Exact`, `Alternatives`, `Unsupported`) and matching becomes a pure comparison.

| phase | before | after |
|---|---:|---:|
| mask assembly | 141.6 ms | **11.4 ms** |
| chart total | 144.0 ms | **14.5 ms** |

**The binary index** (`jagr_index`) came second, because after the above, load was 85–90 % of resolver time. It stores only what resolution reads — sorted versions, and each declaration with the releases that declare it — as a flat little-endian blob (`JHOLJAG1`) beside each cached packument.

| reading 344 packuments (2.27 MB index) | time |
|---|---:|
| gunzip + JSON + prune | 426 ms |
| cache view via index | **15.2 ms** |

Validation is **stat-only** (length + mtime in the header): hashing the packument would spend exactly what the index saves. Stale, truncated, foreign-magic and trailing-byte blobs fall back to JSON. The loader is **self-healing** — anything it had to parse gets an index written.

The first attempt at the index hooked the fetch path and **never fired**: a real install wrote 63 packuments and 0 indexes, because the cache has more than one writer. Making the loader materialise what it parses was the fix; the dead hook was deleted rather than left as noise.

## 1.5 Explainability

* **`jhol why <pkg>`** — every installed copy, its version, path, and the range each dependent demanded, from the lockfile alone. Attribution is *nearest declaring ancestor*, so a nested copy answers for its own dependent.
* **`jhol why-not <pkg>@<range>`** — the **minimal unsat core**: intersect the request with every installed requirement, then shrink greedily (drop one; if the intersection is still empty, it was never needed).

```
$ jhol why-not chalk@^3
the only versions matching it are: 3.0.0
and these requirements forbid every one of them:
  jest-watcher@29.7.0 needs chalk ^4.0.0
```

On a real jest tree the core names **one** dependent, not the thirty that mention chalk. Three outcomes are kept distinct: already installed (answered with its path), published-but-forbidden (the core), nothing published in range.

## 1.6 Policy as input, not audit

**`--as-of <date>`** admits only versions published at or before the cutoff. Fail-safe: a version with no publish date cannot be shown to have existed then, so it is excluded. A dated install never falls back to the flat resolver — it exits 1 with zero packages installed.

```
install --as-of 2020-06-01  → express 4.17.1, 50 packages
install --as-of 2023-06-01  → express 4.18.2, 58 packages
install                     → express 4.22.3, 71 packages
```

Warm repeats: 24.7 s → 8.1 s → **6.2 s**, same tree each time (full packuments cached under a representation-aware key).

**`--allow-license <list>`** — unknown licences are excluded by default; both npm forms are read; SPDX `OR` is treated as the disjunction it is; matching is case-insensitive.

| policy on a real express tree | outcome |
|---|---|
| `MIT` | refused at `qs` (BSD-3-Clause), 0 installed |
| `MIT,BSD-3-Clause` | refused at `setprototypeof` (ISC), 0 installed |
| `MIT,BSD-3-Clause,ISC,Apache-2.0` | **71 packages, 0 violations, 0 unknown** (independently audited) |

**`--exclude-vuln`** resolves, asks OSV about the chosen releases in parallel, bans the vulnerable ones and resolves again (4 rounds, 16 concurrent queries). An exact pin that is vulnerable is **refused with a widening hint**, never silently overridden.

## 1.7 AI-first artifacts

**Models** (`jagr_index`-style content addressing + `jhol-ai`):

```
$ jhol ai inspect --source hf://… --file model.safetensors
100 tensors, 126,851 parameters, header 10752 bytes (data starts at 10760)
```

**10 760 bytes** fetched over two HTTP ranges — the same 10 760 bytes for a 7 GB checkpoint, because a safetensors header maps every tensor to a byte range.

`jhol ai pull` stores files by SHA-256 and materialises by hard link: two projects sharing a checkpoint cost **one inode, one store entry, 520 212 bytes**. Branch refs resolve through `X-Repo-Commit`, so a manifest pins a commit, never a moving name.

The hazard this exposed is worth recording: a project copy and the store entry **share an inode**, so an in-place edit rewrites the stored bytes for every project — and my first version then "repaired" by re-linking the corrupted bytes. Entries are now `0444`, `put` verifies before trusting, and `materialise` refuses bytes that disagree with their own name.

**Python** — three commands, one mechanism:

```
$ jhol axes
macos arm64 · libc unknown · no cuda

$ jhol wheels torch@2.4.1 --python 3.12
20 file(s), 1 compatible: torch-2.4.1-cp312-none-macosx_11_0_arm64.whl

$ jhol pysolve torch@2.4.1 --python 3.12
10 packages resolved in ~1 s (each with its chosen artifact)

$ jhol py install requests --python 3.12
5 distributions in ~1 s, verified per-file, covered by `jhol verify`
```

Five rules had to be right, each found by a failing test rather than a spec reading: `manylinux_2_17_x86_64` is glibc ≥ 2.17 **and** arch (splitting on the first underscore gives arch `17_x86_64`); `manylinux2014` means glibc 2.17; `aarch64` ≡ `arm64`; `cp312-none-…` is version-specific despite `abi: none` (torch's macOS wheels); a Linux wheel on macOS is a *platform* mismatch, not "needs glibc".

**Environments, proofs, replay:**

```
$ jhol env fork exp1
forked exp1 in 797 ms — 690 dirs, 4491 files (4491 cloned, 0 copied), ~0 bytes added

$ jhol attest
attested 260 packages and 0 models at ./.jhol/attestation.json

$ jhol replay paper.json --execute
replay complete: 2024-express-repro          # express 4.18.2 as of 2024-01-01
```

Forks use **copy-on-write** (APFS `clonefile`, Linux `FICLONE`), not hard links: a fork exists to be edited, and a hard link means editing the fork rewrites the original — my first version did exactly that and the test caught it. Attestations are deterministic (sorted keys, no timestamps) and produced by the same verifier that enforces freshness. `replay` executes the very commands a user would type, so it cannot drift from CLI semantics — and refuses to edit `package.json` silently.

**Agent surface.** MCP tools: `jhol_verify_environment` (one verdict per artifact kind), `jhol_axes`, `jhol_why_not` (offline minimal core), `jhol_plan_python` (resolve + **cost**: bytes, cache-aware download split, estimate), `jhol_plan_model` (Hub sizes from HEAD).

# Part II — The engine (JholVM)

## 2.1 Pipeline

```
source → lexer → parser → AST → compiler → bytecode → VM
                                          └→ narrow JIT (counted loops, guards, deopt)
```

NaN-boxed 64-bit values (`0x7FF8` prefix, 44-bit offsets into a flat arena), non-moving mark-sweep GC (non-moving because the interpreter holds raw references), inline caches for store/number/array/string, fused operations, string accumulator, and a JIT that compiles counted loops only when every operation is whitelisted and escape analysis permits.

## 2.2 Gaps closed, and how each was found

| gap | root cause | how found |
|---|---|---|
| **temporal dead zone** | `declare` allocates the slot before compiling the initializer, so a read resolves to it | my own completeness test |
| **arrow-body panic** | arrows were pushed with **no scope**; `declare_pattern` unwraps `scopes.last()`. `var` escaped via hoisting, which is why 44 corpus pairs never caught it | the TDZ test |
| **strict assignment** | the check was in `Op::SetGlobal`; the compiler emits `Op::DefGlobal` for an unresolved assignment | five probes, all of which "looked fine" because `eval` discards values |
| **`Symbol`** | symbols were strings (`"Symbol(x)"`) | **20-idiom differential sweep: 19/20 matched, 1 diverged** |
| **well-known symbols** | `Symbol.iterator` was the string `"Symbol(iterator)"` while the protocol looked up `"@@iterator"` — the two never met, so `[][Symbol.iterator]` was `undefined` | the symbol migration |
| **array destructuring** | patterns indexed the right-hand side instead of iterating it | the same sweep that proved `[...set]` correct |
| **`Promise` + microtasks** | absent entirely | building it |
| `String(undefined)` | a present nil argument was treated as "no argument" | the symbol tests |

**Design notes worth keeping:**

* **TDZ** is a per-block dead-zone set tagged with the function it belongs to, consulted **before** the binding lookup — that ordering is the whole bug. Nested function bodies start with an empty set, so `let f = () => x; let x = 5; f()` stays legal. Dynamic TDZ (a function called before the `let` runs) needs a per-frame initialised bitmap and is documented as such.
* **`Symbol`** is a **tagged interned id** — subtag 3, payload = id, no heap object — so identity is the id: `Symbol("x") !== Symbol("x")`, `Symbol.for("k") === Symbol.for("k")`, `o[sym]` keeps identity. Well-known symbols use the *internal* protocol key as their id, which is what closed the split.
* **Promise** runs off one FIFO microtask queue drained after the entry script and before every timer. Native functions receive no environment, so `resolve`/`reject` are natives **bound** to their promise and jobs are bound natives carrying `[promise, onFulfilled, onRejected, derived]` — the mechanism `bind` already used. Two ordering bugs surfaced: `Promise.resolve(obj)` returned the object because `get_prop(..).is_ok()` is `Ok(undefined)` for a missing key; and a thenable's `then` was called inline where the spec absorbs it in a *job*, shifting every later `.then` one microtask early.

## 2.3 Remaining engine gaps

| gap | state |
|---|---|
| `async`/`await` | rejected at compile time with a clear message; lowering needs suspension points modelled on generators |
| `Promise.all/allSettled/race/any`, `finally`, unhandled rejections | additive on a queue that is now correct |
| `BigInt` | needs a second boxing tag + limb arithmetic |
| `arguments` mapped object | needs the iterator path (now present) |
| regex lookaround/backrefs | largest single item |
| `eval` | attempted; reverted on a UB check |

**On `eval`, the evidence matters.** The attempt swapped `stack`/`frames`/`handlers` around a nested `run_module` and aborted on `eval("1+1")` with `slice::get_unchecked_mut` precondition failure — inside register accessors whose comment states the invariant: *"every frame resizes the stack to its nslots on entry"*. **The stack is not storage, it is a layout.** A correct `eval` needs a separate stack with its own bases, or an explicit stack pointer threaded through `ld`/`st`. Reverted rather than shipped; an engine that aborts on a two-character program is worse than one that reports the gap.

# Part III — Method, and the rules it produced

The recurring shape of every defect this session: **an authority answering with weaker evidence than the question requires.**

| defect | the weak evidence | the question |
|---|---|---|
| five freshness gates | mtime, proof, fingerprint | is the tree what the lockfile authorises? |
| pid-file lock | file contents | is another install running? |
| bundle projection | manifest hash | does this request resolve to this tree? |
| mask alignment | word offsets | does this version satisfy this range? |
| `verify` on esbuild | every lockfile entry | can this package exist here? |
| `Symbol.iterator` | two different strings | is this the protocol key? |
| `Promise.resolve(obj)` | `Ok(undefined)` | is this a promise? |

Rules the session produced, each paid for:

1. **A fast path may save work; it may not decide truth.** Put the authority at the chokepoint, not at each call site — gating call sites took four attempts.
2. **Prefer the mechanism the OS already gets right.** A lock implemented as a file with content is two mechanisms, and the protocol had a hole.
3. **A correctness check must know what is legitimately absent** before calling anything missing.
4. **When data looks missing, check what upstream deleted.** Three features were broken by our own pruning.
5. **Verify the patch applied before believing the measurement.** Twice a patch silently no-opped; once a benchmark described a binary that was never built.
6. **Measure the phase, not the total.** Cold jest moved 31 s → 64 s between runs of the same manifest with only the network changing.
7. **A probe with no output is not evidence.** `jhol eval` discards values; five strict-mode cases "passed" while doing nothing.
8. **Two sources of truth for one fact is how tests start lying.** A symbol test module asserting on `Debug` strings was deleted in favour of the node-verified corpus.
9. **Fail loudly, never silently wrong.** A reproducibility feature that falls back to today is worse than one that refuses.
10. **No structural change without its acceptance test** — hence `eval` reverted and `Promise` planned before it was built.

# Part V — Risks, non-goals, and what is next

**Risks.** Warm-install gap (measured, cause known, unfixed). Network-bound payload. `async`/`await` absence. 179 `JHOL_*` knobs, classified but not retired. `eval`, `BigInt`, regex depth. Python install lacks console scripts and RECORD-based uninstall. Peer dependencies advisory by default.

**Non-goals, stated so scope stays honest.** Not a registry or model hub; not a Python solver (delegate to uv/pip through the adapter and represent the result); not a training or inference framework; no copying — the moat is the node shape and bitmap policy memory, never another tool's algorithm or CLI.

**Next, in order.**

1. **Warm-install materialisation** — project a prepared tree for explicit installs instead of writing directories one by one.
2. **`async`/`await`** — suspension points modelled on the generator machinery, on top of the microtask queue that is now correct.
3. **`Promise` combinators and unhandled rejections** — additive.
4. **Retire the first escape hatches** (`ENV-AUDIT.md` §2), starting with the single-pass layout whose reason is now historical.
5. **`Symbol`-based `arguments`**, then regex lookaround.

# Addendum — attacking the instance resolver

The resolver was not attacked for speed first. It was attacked for **correctness of
its own promises**, and that is what produced the speed.

## What was wrong, and how it was proved wrong

Three tests were written before any fix, and two of them failed on the spot:

| probe | result before the fix |
|---|---|
| an `npm:` alias beside its real package | `instances = [app, bar, foo]` — the alias **was not there**; `node_modules/aliased` would never be created |
| two overlapping ranges (`^1.0.0` and `1.2.3`) | `c = ["1.9.0", "1.2.3"]` — two copies of a package that never conflicted |
| a lone range, nothing competing | passed — and must keep passing (no silent downgrade) |

The first probe is the serious one. It is not a slow path or an ugly tree: a
dependent asks for `aliased`, the resolver answers "yes, `foo@1.0.0`", the installer
writes `node_modules/foo`, and the failure happens at *runtime*, in a program that
installed "successfully". Reuse was keyed on `(version)` where identity is
`(installed_as, version)`.

The second is a quality defect of exactly the kind that is easy to rationalise as
"npm does it too". It does not matter who else does it: `c` satisfied both demands,
and we wrote two directories, downloaded two tarballs, extracted two copies and
verified two entries for it.

## The fixes, and why they are not just a patch

**Identity is the installed name.** One predicate, one test, and the tree can no
longer materialise a package under a name nobody asked for.

**Version choice scores coverage of the visible future.** A candidate is scored by
how many demands already waiting in the worklist it satisfies, newest-first, with
coverage as a *tie-breaker* — so the rule can only ever move a choice from "newest
that works" to "newest that works for more dependents", never below what the
triggering demand asked for. That property is what makes it safe to apply always,
rather than behind a knob: the invariant list for this module is now determinism,
minimality, identity, proportionality, and explanation.

**Metadata is read on demand.** This was found by measuring the fix's own
neighbours: the jest run took 2.9 s and the tree was 266 packages, so 12 484
behaviour was the only place the time could be. The pre-pass built a per-package
view for every packument in the cache before reading a single requirement.

| jest@29.7.0 over a 12 484-packument cache | before | after |
|---|---:|---:|
| resolve | 2 883 ms | **35 ms** (82×) |
| tree | 266 instances / 260 packages / 6 duplicates | identical |
| express@4.18.2, same cache | — | 4.1 ms |

The tree is byte-identical, which is the point: this was not a trade, it was work
nobody asked for. The restored invariant is stated as one line — **resolution costs
what the tree costs, not what the cache costs** — and it is why the explainability
commands (`why`, `why-not`, `--as-of`) can run the full resolver on every
invocation.

## The honest negative result

jest's instance count did **not** change: 266 before, 266 after. Its six duplicates
are genuine major conflicts (`ansi-styles@4` for `log-symbols` and `@5` for
`jest-cli`, `semver@6` and `@7`). Reporting this matters more than the fix does:
the sharing rule is correct and tested, but on the largest real tree available it
buys nothing. It will pay on graphs whose demands merely overlap, which is the
common shape for a pinned transitive dependency.

## What is deliberately not done yet

A post-pass that merges two instances when one version satisfies both was
considered and rejected for now, for a specific reason: changing an instance's
version changes its **dependency set**, and the worklist keys dependents by
`"package@version"` strings. Merging would leave stale requirements that create
instances nothing references. The clean form of that idea needs edges keyed by
instance index instead of a display string — a structural change that deserves its
own acceptance test rather than a 40-minute window.

`every_recorded_demand_is_satisfied` is now a permanent property test over a graph
containing an overlap, a pin, an alias and a real conflict. Any future change to
version choice has to keep that promise.
