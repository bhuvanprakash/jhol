\begin{jholabstract}
\noindent
Modern JavaScript package managers spend a large fraction of cold-install time---and nearly all of warm-install time---on storage: tarball placement, integrity verification, unpacking, and projection into \pkg{node_modules}. Existing designs duplicate bytes across compressed archives, unpacked trees, and per-project links, and they index those bytes with formats that force JSON parsing or directory walks on every reuse. Concurrent multi-project installs further contend on coarse locks around shared caches.

This paper presents the \textbf{Jhol storage stack}, centered on \textbf{JAGR-S} (\pkg{.jagrs}): a succinct mmap-backed store with (i)~SwissProbe-16 SIMD fingerprint probing, (ii)~broadword $O(1)$ Elias--Fano monotone indexing, (iii)~sheaf spectral locality that co-locates co-installed packages by the Fiedler partition of the Cellular Sheaf Laplacian~\cite{prakash2026sheaf}, (iv)~lock-free generation epochs, and (v)~bounded header-only \texttt{msync}. Supporting layers include completeness-marked \pkg{store_unpacked} trees, the experimental JGrid materialization pyramid, and SRI harvest from npm \pkg{_cacache}.

Microbenchmarks on Apple Silicon and Linux x86\_64 show probe latency $24.5\,\mathrm{ns}\!\to\!1.8\,\mathrm{ns}$ ($13.6\times$), Elias--Fano select $82\!\to\!3.4\,\mathrm{ns}$ ($24.1\times$), and tarball slice lookup $1.42\,\mu\mathrm{s}\!\to\!0.08\,\mu\mathrm{s}$ ($17.7\times$). Because FastStream~\cite{prakash2026sheaf} already eliminates the triple-write penalty on the default path, JAGR-S ships as an \emph{opt-in} mirror (\pkg{JHOL_JAGRS_MIRROR=1}). End-to-end, SRI harvest recovers 63\% of tarballs on a warm developer machine for a 70-package fixture without trusting foreign caches until the local SRI verifier accepts them.
\end{jholabstract}

\begin{takeaway}[Paper~II in one sentence]
JAGR-S pushes artifact lookup into the nanosecond regime (\metric{1.8\,ns} probes, \metric{17.7$\times$} faster slice reads) via SwissProbe-16, broadword Elias--Fano, and sheaf spectral co-location---but ships \emph{opt-in}, because FastStream already won the default cold path.
\end{takeaway}

\section{Introduction}
\label{sec:intro}

A package manager has two jobs: \emph{resolve} a satisfying version assignment, and \emph{materialize} the corresponding artifacts. The companion paper~\cite{prakash2026sheaf} reformulates resolution through cellular sheaves, Wilsonian renormalization, and Forman--Ricci curvature, and introduces \textbf{FastStream} zero-copy stream-to-store ingestion that removes the classical triple-write penalty (fetch $\to$ \pkg{.tgz} $\to$ unpack $\to$ link). Once the assignment exists, however, wall-clock time on warm paths is dominated by bytes:
\begin{equation*}
\text{Registry}\to\text{tarball}\to\text{SRI verify}\to\text{unpacked tree}\to\pkg{node_modules}.
\end{equation*}
Production managers (npm, pnpm, Yarn, Bun) converge on content-addressed caches, but they leave three structural gaps that this paper addresses.

\begin{enumerate}
  \item \textbf{Index cost.} Lookups either parse JSON indexes, walk directory trees, or maintain sidecar databases whose latency dwarfs the mmap cost of reading the artifact itself.
  \item \textbf{Layout locality.} Packages that always co-install (\pkg{react}/\pkg{react-dom}, \pkg{@babel/*}) are scattered by hash, defeating OS readahead during mass materialization.
  \item \textbf{Cross-tool waste.} A machine that already holds npm \pkg{_cacache} or another project's store still re-downloads the same SRI-identified bytes.
\end{enumerate}

\section{Background}
\label{sec:background}

\subsection{Content-addressed artifact stores}
A \emph{content-addressed store} (CAS) names artifacts by cryptographic digests of their bytes rather than by mutable paths. Git~\cite{git}, Nix~\cite{nix}, pnpm's content store~\cite{pnpm}, and npm's \pkg{_cacache}~\cite{cacache} all exploit the property that identical bytes imply identical keys, enabling deduplication and deterministic reuse. Package managers additionally carry \emph{registry identities} (\pkg{name@version}) that must map to tarball bytes and, after inflation, to directory trees $T_{P,v}$.

\subsection{Memory-mapped I/O}
\texttt{mmap} maps file bytes into the process address space, letting lookups become pointer arithmetic plus bounds checks rather than \texttt{read}/\texttt{pread} syscalls. JAGR-S and JGrid both treat on-disk tables as immutable or append-only regions behind \texttt{Arc<Mmap>}, so hot paths return \texttt{\&[u8]} slices without intermediate buffers. Writers synchronize only dirty header ranges via \texttt{msync}, not whole files.

\subsection{Swiss tables and SIMD probing}
Swiss-table hash maps (lineage from cuckoo hashing~\cite{cuckoo}) store a compact \emph{control byte} per slot---the H2 fingerprint---so probes compare 8-bit tags before 64-bit keys. Grouped probing (16 slots per cache line) enables SIMD lane comparisons. JAGR-S adapts this pattern to a fixed-capacity mmap table with open addressing.

\subsection{Elias--Fano succinct indexes}
Elias--Fano~\cite{elias1974} encodes a monotone sequence of $n$ integers in $[0,U)$ using $n\lceil\log_2(U/n)\rceil + 2n$ bits, supporting $O(1)$ \texttt{select} (find the position of the $i$-th one-bit) and near-optimal space. JAGR-S uses Elias--Fano for alias offset streams; v3 replaces linear bit scans with \texttt{broadword\_select64}, a branchless popcount tree on 64-bit words.

\paragraph{Non-goals.}
We do not defend against a malicious registry that serves bytes matching a wrong but well-formed SRI for an unintended version; version selection is the resolver's job~\cite{prakash2026sheaf}. We also do not encrypt cache contents at rest.

\paragraph{Default vs.\ opt-in.}
Measurement on a Next.js-scale tree ($\sim$300 packages) showed: (i)~default FastStream + \pkg{store}/\pkg{store\_unpacked} warm installs in 8--17\,ms; (ii)~enabling JAGR-S mirror adds $\sim$128\,MB with parity warm time; (iii)~default JGrid ingest adds $\sim$185\,MB and $\sim$0.9\,s without beating warm relink. \section{JAGR-S: format and algorithms}
\label{sec:jagrs}

JAGR-S (\textbf{J}hol \textbf{A}rtifact \textbf{G}raph \textbf{R}esolution \textbf{S}tore) replaces JSON \pkg{store\_index.json} and sharded directory walks with three mmap-friendly files under \pkg{<cache>/v3/}:

\begin{verbatim}
~/.jhol-cache/v3/
  manifest.jagrs   # fixed header + SwissProbe table
  objects.jagrs    # append-only tarball blob log
  aliases.jagrs    # name@version -> content hash (+ string table)
\end{verbatim}

\subsection{SwissProbe-16}
\label{sec:swiss}

Let $k$ be a lookup key and $h_1 = H_{64}(k)$ its 64-bit hash. The H2 control tag is
\begin{equation}
h_2 = \bigl((h_1 \gg 56)\;\mathrm{as}\;\mathtt{u8}\bigr)\;|\;\texttt{0x80},
\label{eq:h2}
\end{equation}
forcing the high bit so empty slots (\texttt{0x00}) are distinguishable. Probing starts at index $i_0 = h_1 \bmod C$ for table capacity $C$ and examines up to $\lceil \log_2 C \rceil$ slots. Within each 16-slot \emph{group} aligned to a cache line, SIMD compares all control bytes to $h_2$ before touching full \texttt{key\_hash} fields.

\begin{algorithm}[H]
\caption{SwissProbe lookup}
\label{alg:swiss}
\begin{algorithmic}[1]
\Require key hash $h_1$, kind $\tau$, table $T[0..C-1]$
\Ensure entry $e$ or $\bot$
\State $h_2 \gets ((h_1 \gg 56) \bmod 256) \;|\; \texttt{0x80}$
\State $i \gets h_1 \bmod C$
\For{$r = 1$ \textbf{to} $\lceil \log_2 C \rceil$}
  \If{$T[i].\text{kind} = \texttt{empty}$}
    \State \Return $\bot$
  \EndIf
  \If{$T[i].h_2 = h_2$ \textbf{and} $T[i].\text{kind}=\tau$ \textbf{and} $T[i].\text{key}=h_1$}
    \State \Return $T[i]$
  \EndIf
  \State $i \gets (i+1) \bmod C$
\EndFor
\State \Return $\bot$
\end{algorithmic}
\end{algorithm}

Measured on 10k successful lookups (Apple Silicon, release build): \textbf{24.5\,ns $\to$ 1.8\,ns} per probe ($13.6\times$). Legacy entries with \texttt{h2\_tag=0} remain compatible: the implementation falls back to full key comparison.

\subsection{Broadword Elias--Fano select}
\label{sec:ef}

Alias offset streams are monotone and encoded in Elias--Fano form: a \emph{low} bit-packed region and a \emph{high} bitvector where \texttt{select}$(i)$ returns the position of the $(i{+}1)$-th set bit. Version 3 implements \texttt{broadword\_select64} using a fixed-depth popcount tree on 64-bit words---four instructions per word, no data-dependent branches.

\begin{algorithm}[H]
\caption{\texttt{broadword\_select64}$(w, r)$}
\label{alg:select}
\begin{algorithmic}[1]
\Require 64-bit word $w$, rank $r \ge 1$
\Ensure bit index of $r$-th one in $w$, or $64$ if $r > \mathrm{popcount}(w)$
\State $c_{16} \gets \mathrm{popcount}(w \land \texttt{0x0000FFFF0000FFFF})$
\If{$r \le c_{16}$} \State $w \gets w \land \texttt{0x0000FFFF0000FFFF}$ \Else \State $w \gets w \gg 32$; $r \gets r - c_{16}$ \EndIf
\State \Comment{repeat at 16-, 8-, 4-, 2-bit levels}
\State \Return index of remaining one-bit via \texttt{ctz}
\end{algorithmic}
\end{algorithm}

Measured: \textbf{82\,ns $\to$ 3.4\,ns} per \texttt{select} ($24.1\times$). Combined with SwissProbe, tarball slice resolution drops from \textbf{1.42\,$\mu\mathrm{s}$ $\to$ 0.08\,$\mu\mathrm{s}$} ($17.7\times$).

\subsection{Sheaf spectral locality}
\label{sec:spectral}

Let $G=(V,E)$ be the install graph at append time and $L_{\mathcal{F}}=\delta_0^*\delta_0$ the Cellular Sheaf Laplacian from~\cite{prakash2026sheaf}. The \textbf{Fiedler vector} $\mathbf{v}_2$ (eigenvector for the algebraic connectivity $\lambda_2$) induces a bipartition $V=V_1 \sqcup V_2$. When appending to \pkg{objects.jagrs}, JAGR-S tags each object with \texttt{(sheaf\_cluster, fiedler\_partition)} and groups consecutive appends from the same side of the cut. Co-installed packages therefore occupy sequential disk ranges, improving readahead during batch materialization.

\begin{proposition}[Heuristic locality]
If packages $a$ and $b$ are connected in $G$ and $|v_2(a)-v_2(b)|$ is small, placing their blobs adjacently reduces expected page faults per unit link materialization compared to hash-random placement.
\end{proposition}

Measured batch page-cache miss rate during 70-package materialization: \textbf{14.2\% $\to$ 1.6\%} ($8.9\times$ fewer misses). Spectral tags are computed from the \emph{current} install graph; online updates as the graph grows remain future work (\S\ref{sec:conclusion}).

\subsection{Lock-free generations and zero-copy slices}
\label{sec:lockfree}

Writers hold a process-local mutex for append serialization but expose cross-process coherence through an \texttt{AtomicU64} \texttt{generation} mirrored in the mmap header. Each successful \texttt{store()} performs \texttt{generation\_atomic.fetch\_add(1, Release)}; readers load with \texttt{Acquire} before trusting offsets.

\texttt{get\_tarball\_slice} returns \texttt{\&[u8]} into an \texttt{Arc<Mmap>} of \pkg{objects.jagrs}---no \texttt{Vec} allocation on the hot path. \texttt{flush()} calls \texttt{flush\_range(0, sizeof(ManifestHeader))}, synchronizing only the 64-byte header. Measured header sync: \textbf{3.8\,ms $\to$ 0.04\,ms} ($95\times$).

\begin{lstlisting}[caption={Zero-copy slice (conceptual).},label={lst:slice}]
pub fn get_tarball_slice(&self, key_hash: u64)
    -> Option<&[u8]>
{
    let (entry, _) = self.probe(key_hash, KIND_TARBALL)?;
    let mmap = self.objects_mmap.read().as_ref()?;
    let start = entry.offset as usize;
    let end = start + entry.size as usize;
    Some(&mmap[start..end])
}
\end{lstlisting}

\subsection{Soundness at open time}
\label{sec:soundness}

\begin{theorem}[Safe indexing]
If open rejects manifests unless \texttt{capacity} is a power of two in $[1,2^{24}]$ and file length covers the full table, then every \texttt{JagrsEntry} slice and alias record slice is in-bounds for all validated offsets stored while the manifest was consistent.
\end{theorem}

This closes the class of vulnerabilities where a truncated manifest led to \texttt{from\_raw\_parts} with out-of-range lengths (E93/E144). Corrupt entries fail closed with \texttt{Err} rather than undefined behavior.

\section{Unpacked store completeness}
\label{sec:complete}

FastStream projects inflated bytes into \pkg{store\_unpacked/<shard>/<hash>/}. A classical failure mode is a \emph{partial} directory---often only \pkg{package.json}, the first tar entry---that subsequent installs treat as complete because \texttt{exists()} returns true. Symlinks into such directories poison warm installs and nested lockfile paths (E145).

\paragraph{Marker rule.}
After a full extract, write \pkg{.jhol-extract-complete}. Define
\begin{equation*}
\mathrm{complete}(D) \iff
\exists\,\pkg{.jhol-extract-complete}\in D
\;\lor\;
\exists\,\text{regular file } f\in D,\; f \notin \{\pkg{package.json}, \text{marker}\}.
\end{equation*}
Manifest-only directories, dangling symlinks, and incomplete siblings trigger \texttt{remove\_store\_dir} + re-extract. All materialization sites consult \texttt{store\_extract\_complete} before short-circuiting.

\begin{algorithm}[H]
\caption{Ensure unpacked store directory}
\label{alg:complete}
\begin{algorithmic}[1]
\Require tarball bytes $B$, target directory $D$
\Ensure complete tree at $D$
\If{$\mathrm{complete}(D)$} \State \Return
\EndIf
\State $\mathrm{remove\_store\_dir}(D)$
\State $\mathrm{extract\_tar}(B, D)$
\State write marker \pkg{.jhol-extract-complete} in $D$
\end{algorithmic}
\end{algorithm}

This invariant is independent of JAGR-S: the default \pkg{store\_unpacked/} path relies on it for correctness; JAGR-S mirrors are irrelevant if unpacked siblings are wrong.

\section{JGrid materialization pyramid}
\label{sec:jgrid}

\textbf{JGrid} is a single-file \pkg{.jgrid} format (magic \pkg{JHGR0002}) implementing a three-tier materialization pyramid. Lookups use mmap + a Swiss table over SHA-256 block hashes ($\sim$2--6\,ns per hit in microbench).

\begin{table}[H]
\centering
\caption{JGrid tiers and mechanisms.}
\label{tab:jgrid}
\small
\begin{tabular}{@{}lllp{4.2cm}@{}}
\toprule
\textbf{Tier} & \textbf{Target} & \textbf{Latency class} & \textbf{Mechanism} \\
\midrule
L0 & Whole \pkg{node\_modules} & $\le$200\,$\mu$s & One \texttt{clonefile}/reflink of pre-built bundle \\
L1 & Per-package tree & $\le$50\,$\mu$s & Clone-ready directory per manifest \\
L2 & Content blocks & $\le$500\,$\mu$s & Swiss SHA-256$\to$(offset,size) in \pkg{JHGR0002} \\
\bottomrule
\end{tabular}
\end{table}

\paragraph{On-disk regions.}
The 256-byte \texttt{GridHeader} records offsets for control words, hash slots, block data, manifests, string table, and optional tree index (L1). Blocks are 4096-byte aligned. Materialization tries L0 $\to$ L1 $\to$ L2 and falls back to the default store path on miss.

\paragraph{Opt-in ingest.}
Ingest (\pkg{JHOL\_JGRID\_INGEST=1}) walks an installed tree post-install. On a Next.js-scale project, default ingest added $\sim$185\,MB and $\sim$0.9\,s without beating the existing warm relink path ($\sim$30\,ms with daemon attach). L0 bundle creation on ingest---so the fastest tier can win end-to-end---remains open work.

\section{SRI harvest: local-origin bytes}
\label{sec:harvest}

npm's \pkg{_cacache} addresses content by the same SRI string lockfiles already carry. Given $s=\texttt{sha512-}\langle\text{base64}\rangle$, decode to hex digest $d$ and construct the path in $O(1)$:
\begin{equation}
\mathrm{path}(s) = \texttt{content-v2/sha512/}d_{0:2}\texttt{/}d_{2:4}\texttt{/}d_{4:}.
\label{eq:cacache}
\end{equation}

No directory scan or secondary index is required.

\begin{algorithm}[H]
\caption{SRI harvest}
\label{alg:harvest}
\begin{algorithmic}[1]
\Require integrity string $s$, cache roots $R$
\Ensure verified bytes $B$ or $\bot$
\If{harvest disabled} \State \Return $\bot$ \EndIf
\For{each root $r \in R$}
  \State $p \gets \mathrm{path}(s)$ relative to $r$
  \If{not readable($p$)} \textbf{continue} \EndIf
  \State $B \gets \mathrm{read}(p)$
  \If{$\mathrm{verify\_sri}(B, s)$} \State \Return $B$ \EndIf
\EndFor
\State \Return $\bot$
\end{algorithmic}
\end{algorithm}

Harvest integrates at the single tarball choke point \texttt{download\_tarball\_to\_store\_hash\_only}: harvested bytes still pass through the normal SRI pipeline before \pkg{store/} admission---a foreign cache can only be \emph{ignored}, never trusted blindly. Disable with \pkg{JHOL\_NO\_HARVEST=1}.

On a warm developer machine, a 70-package fixture harvested \textbf{44/70 (63\%)} of tarballs (median cold 1.88\,s $\to$ 1.76\,s). Next.js-scale trees with freshly published versions harvested fewer entries (4/300) because npm's cache lacked those releases---honest measurement, not a implementation defect.

\section{Integration with FastStream}
\label{sec:faststream}

The companion sheaf paper~\cite{prakash2026sheaf} introduces \textbf{FastStream}: HTTP/2-multiplexed download directly into the content store while selective extraction runs on the byte stream, eliminating the intermediate ``write \pkg{.tgz}, read \pkg{.tgz}, unpack'' cycle. JAGR-S is \emph{downstream} of FastStream: it indexes bytes FastStream (or harvest) already verified.

\begin{itemize}
  \item \textbf{Default path:} FastStream $\to$ \pkg{store/<hash>.tgz} + \pkg{store\_unpacked/} + completeness marker. Lookups use an in-process store index with SRI sidecars (\pkg{.tgz.sri}).
  \item \textbf{Mirror path:} When \pkg{JHOL\_JAGRS\_MIRROR=1}, an additional append to \pkg{v3/objects.jagrs} and SwissProbe insert occur. \texttt{soul\_path} falls back from JAGR-S slices to \pkg{store/} tarballs if the mirror is absent.
  \item \textbf{Warm reuse:} Global Resolution Memory~\cite{prakash2026grm} and capsule fast paths replay lockfile layouts without re-resolution; storage correctness reduces to index lookup + completeness checks.
\end{itemize}

Storage does not re-derive version assignments; it assumes the resolver and law layer~\cite{prakash2026sheaf} already produced a verified assignment $\sigma$.

\subsection{Ablation: opt-in decision}
\label{sec:ablation}

We ablated three secondary-store knobs on the same hardware:

\begin{enumerate}
  \item \textbf{JAGR-S mirror on:} $+128$\,MB disk, warm time statistically indistinguishable from default; no user-visible win on the measured warm path.
  \item \textbf{JGrid default ingest on:} $+185$\,MB, $+0.9$\,s install tail on first ingest, warm parity at best; L0 bundles not created.
  \item \textbf{Both off (shipped default):} lean cache, full correctness, FastStream-only ingestion.
\end{enumerate}

\textbf{Decision.} Ship JAGR-S and JGrid as opt-in research artifacts. The algorithms stand alone; the product policy avoids taxing every install for mirror bytes that the primary store already holds.

\section{Related work}
\label{sec:related}

\paragraph{Content-addressed package stores.}
pnpm~\cite{pnpm} uses a content store with hardlinks into per-project \pkg{node\_modules}; Nix~\cite{nix} builds purely functional trees from CAS paths; Bun and npm maintain tarball caches with JSON or SQLite indexes. JAGR-S specializes the \emph{index structure} (SwissProbe + Elias--Fano) and \emph{physical layout} (sheaf spectral tags) for JavaScript-scale graphs with frequent warm reuse.

\paragraph{Succinct data structures.}
Elias--Fano~\cite{elias1974} and broadword techniques are classical in information retrieval; Swiss-table probing inherits from cuckoo hashing~\cite{cuckoo}. To our knowledge, combining sheaf Laplacian Fiedler partitions with append placement in a package-manager artifact store is new.

\paragraph{Cross-tool cache reuse.}
Yarn Plug'n'Play and pnpm reduce duplication \emph{within} one tool. SRI harvest reuses \emph{another} tool's cache by shared cryptographic identity (\pkg{sha512-} in lockfiles), with double verification.

\paragraph{Companion papers.}
Topological resolution, FastStream ingestion, and sheaf invariants appear in~\cite{prakash2026sheaf}. Global Resolution Memory and Instant Lock warm replay appear in~\cite{prakash2026grm}. This paper completes the \emph{store} layer of Jhol's decide/store/reuse agenda.

\begin{caveat}[Why JAGR-S is opt-in]
A second on-disk mirror that adds $\sim$128\,MB without beating warm relink is a tax, not a feature. Measurement---not aesthetics---decides the default.
\end{caveat}

\section{Conclusion}
\label{sec:conclusion}

We presented Jhol's storage stack centered on \textbf{JAGR-S v3}: a succinct, lock-free, spectrally laid-out artifact store; completeness-marked unpacked trees; an experimental JGrid pyramid; and SRI harvest. Microbenchmarks show order-of-magnitude gains on probe, select, and slice resolution; systems measurement shows default FastStream + \pkg{store}/\pkg{store\_unpacked} already wins warm installs, so secondary stores remain opt-in.

\subsection{Limitations and future work}
\begin{itemize}
  \item \textbf{Online spectral layout:} co-clustering tags are computed from the install graph at append time; dynamic graphs need incremental Fiedler updates.
  \item \textbf{Byte unification:} naive deduplication of \pkg{store/} tarballs vs.\ \pkg{store\_unpacked/} saves only 0.47\,MB on a Next.js tree (E16); compressed-store unification remains open.
  \item \textbf{JGrid L0 bundles:} ingest should emit L0 clone-ready bundles so the fastest tier can beat warm relink end-to-end.
  \item \textbf{HTTP/2 default tarballs:} cold install latency is connection-bound; Jhol's reqwest HTTP/2 path reduces tail latency on multi-tarball installs (companion measurement series).
\end{itemize}
