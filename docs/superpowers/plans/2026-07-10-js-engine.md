## Goal

Build a **from-scratch JavaScript engine** (`crates/js-engine`) that replaces QuickJS (`quickjs-rusty`) in jhol-runtime. The engine leverages jhol's unique architecture — tropical graph algebra, CAS, JAGR three-layer analysis, lock-free GRM, Markov predictor, FUSE mount, offline trees, binary cache — to achieve **native-speed execution** for 95%+ of package-manager workloads, with zero external JS engine dependencies.

**Only 1 external runtime dependency: `cranelift` (codegen). Everything else is our code.**

## The Core Insight

| Other Engines | js-engine (Jhol-Native) |
|---------------|-------------------------|
| Parse at runtime | Parse at **install time** (once per content hash) |
| Resolve modules at runtime | **Pre-link all imports** via tropical graph at install |
| JIT warmup on first runs | **AOT native code** ready before first run |
| Inline cache learned at runtime | **Static IC baked in** from global type flow |
| GC for all allocations | **Escape analysis → stack/arena** for 80% of objects |
| Generic module loader | **FUSE intercept → direct native module handoff** |

## Architecture: 4 Tiers (All Jhol-Native)

```
INSTALL TIME (jhol install)
┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. Tropical Graph → load_order_from(entry) → tree_shake() = dead code elim  │
│ 2. For each module in order:                                                │
│    Parser (our own) → AotAst → SCCP + Escape + GVN → Cranelift + Custom ABI │
│       + SIMD → native .so → CAS.put(hash(source + deps_hash), .so)          │
│ 3. JAGR Layer 1 (topological) → hot module list                            │
│    JAGR Layer 2 (spectral/Betti) → cyclic modules → Tier 2 fallback        │
│    JAGR Layer 3 (MaxSAT) → optimal inlining budget                         │
│ 4. OfflineCache.save_tree() + BinaryCache → air-gap ready                  │
│ 5. Markov.learn_from_sequence(installed_packages)                          │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
RUN TIME (jhol run / jhol exec / lifecycle scripts)
┌─────────────────────────────────────────────────────────────────────────────┐
│ TIER 0: AOT Native (95% of code)                                            │
│   dlopen(CAS.get(hash)) → call native function                              │
│   Zero parse, zero resolve, zero JIT, native speed                          │
│   FUSE mount intercepts require/import → returns native entry              │
├─────────────────────────────────────────────────────────────────────────────┤
│ TIER 1: Lifecycle Fast Path (4% - postinstall, build, test)                │
│   Region allocator + pre-linked modules + no GC                            │
│   Custom bytecode for glue code, direct FFI to native modules              │
├─────────────────────────────────────────────────────────────────────────────┤
│ TIER 2: Full Interpreter (1% - eval, dynamic import, REPL)                 │
│   Our own bytecode VM, NaN-boxed values, hidden classes                    │
│   Only for code AOT rejected (dynamic features)                            │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 8 Breakthroughs (The "Unfair Advantages")

### 1. Tropical Graph → Static Linking
At install time, tropical graph gives optimal module sequence. Every module gets all imports statically resolved to native function pointers. No runtime `require`/`import` machinery.

### 2. CAS + Binary Cache → Zero-Redownload Native Code
Content hash = source + resolved deps + jhol version. On install: reuse existing `.so` or compile new. On run: `dlopen` → execute. Zero parse/compile at runtime.

### 3. JAGR Three-Layer → Optimization Budget Allocation
- Layer 1 (topological): high fan-in modules → aggressive inlining
- Layer 2 (spectral/Betti): cyclic modules → conservative opts, Tier 2 fallback
- Layer 3 (MaxSAT): global inlining budget → optimal code size vs speed

### 4. Global SCCP + Value Numbering Across Module Graph
Sparse Conditional Constant Propagation runs **globally** across all modules at install time. `const x = 1; export {x}` → every importer sees `x` as literal `1`, dead code eliminated, calls inlined.

### 5. Escape Analysis → Stack/Arena Allocation
At AOT time, analyze every object allocation. Non-escaping → stack or arena. Eliminates 80%+ of GC pressure for typical lifecycle scripts.

### 6. Static Polymorphic Inline Caching (Baked In)
From global type flow, exact shape set at each call site known at compile time. Generate native `cmp/jmp` chains for top 1-3 shapes. **No JIT warmup** — ICs compiled in.

### 7. Custom SIMD-Aware Array Ops
Detect `array.map`, `array.reduce`, typed array loops at AOT time. Emit Cranelift IR with explicit SIMD (AVX2/NEON) vector ops. 10-50x faster on numeric arrays.

### 8. Native JS Calling Convention (Register-Tagged)
`JsValue` in registers (NaN-boxed). Hot functions use custom ABI: tagged values in RAX, RDX, RCX, R8-R11. Zero stack spills for typical call chains.

## Critical Decisions (Resolve Before Phase 1)

### Decision 1: Parser Scope
| Option | Lines | Ship | npm Compat | Risk |
|--------|-------|------|------------|------|
| **Full ES2024** | ~2,500 | +2 weeks | 100% | Higher bug surface |
| **Lifecycle Subset** | ~800 | baseline | 95% (rejects `eval`/`with`/dynamic import at parse) | Some packages fail at install with clear error |

**Recommendation**: Lifecycle Subset. Reject unsupported syntax at install time with actionable error. Add full support incrementally post-ship.

### Decision 2: QuickJS Removal Timeline
| Option | Pros | Cons |
|--------|------|------|
| **Drop Now** | Forces completion, smaller binary, no maintenance burden | Breaks if Phase 1-11 slip |
| **Keep as `--legacy-engine`** | Safe fallback, gradual migration | Larger binary, dual maintenance |

**Recommendation**: Keep as `--legacy-engine` feature flag for 1 release (jhol 1.1.x), remove in 1.2.0. Feature-gate js-engine behind `js-engine` Cargo feature (default on).

## Quality Guarantees (No Loss)

1. **Full ECMAScript 2024 compliance** via Test262 in CI (Tier 2 covers all dynamic features)
2. **AOT-eligible subset**: static imports, no `eval`, no dynamic `import()`, no `new Function`, no `with`
3. **Auto-fallback**: anything outside subset → Tier-2 bytecode interpreter (correct, slower)
4. **No silent miscompilation**: AOT and interpreter produce identical results (verified by differential testing in CI)
5. **Install-time errors**: unsupported syntax rejected at `jhol install` with file:line:col + suggestion
